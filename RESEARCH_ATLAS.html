01 / MISSION

최종 목표와 운영 철학

문제 입력에서 근거 있는 판정까지

연구 질문을 받아 ① 사실 자료를 수집하고 ② 경쟁하는 반증 가능 가설을 생성하고 ③ 독립 평가기에 의해 실제 코드를 시험하며 ④ 제한된 범위의 결론을 보존하는 완결형 연구 루프를 구현한다.

LLM의 자기평가나 합의는 과학적 증거가 아니다. 독립 실험·통제된 평가·재현 기록이 판정의 근거다.
Non-goals / 현재 범위 밖
  • Google·Sakana의 비공개 모델을 동일하게 복제했다는 주장
  • 검증되지 않은 연구 성과나 수익 실현 약속
  • 시작부터 대규모 Swarm·GPU 클러스터·분산 시스템 구축
  • 승인 없는 실거래·외부 게시·서버 배포·자격증명 사용
  • 코드 실행 성공을 곧 과학적 발견으로 취급

03 / DESIGN BLUEPRINT

E2E 연구 엔진 아키텍처

아래 여섯 단계는 과학적 기능이다. 코드 구현 시에는 Director·Discovery·Hypothesis·Experiment·Evaluation·Evolution·Memory·UI의 8개 논리 패키지로 배치한다. 8개 서버가 필요한 것은 아니다. 각 단계를 선택해 입력·출력·검증 기준을 확인할 수 있다.

Human research contract → measured experiment → evidence-linked verdict
REFERENCE: ROBIN / CO-SCIENTIST

01. Evidence Discovery

실제 문헌·데이터·사례를 수집하고 출처 및 무결성을 기록한다.

I/O CONTRACT & SAFEGUARDS
  • 입력: 승인된 연구 문제·검색 공역
  • 출력: Source 객체·해시·수집일·라이선스
  • 검증: 허위 출처·부분 원문·권한 누락 차단
연구 Director → 여섯 기능 → 검증 판정실패 결과는 Hypothesis와 Discovery에 환류종료 조건: 증거가 연결된 결과 + 연구 기록

연구 상태의 8개 핵심 객체

ResearchGoal / Source / Hypothesis / Experiment / Run / Evaluation / Decision / Artifact

각 Run은 코드 버전, 환경, 시드, 데이터 해시, 평가기 버전, 원시 로그와 연결된다.

배포 원칙

Mac mini + Python + SQLite + 제한된 Docker + 공급자 API

순차 실행을 우선하고, 병렬 실험·클라우드 GPU·다중 도메인은 검증 후 선택적으로 추가한다.

허용되는 최종 판정

  • SUPPORTED_WITH_LIMITATIONS — 테스트된 범위에서 제한적으로 지지
  • REFUTED — 가설을 반박하는 관측
  • INCONCLUSIVE — 근거·검정력이 부족하거나 결과가 불안정
  • BLOCKED — 데이터·권한·안전·실행 조건 미충족

자동 방어 테스트 12개

재실행 일치, 원본 무결성, 허위 인용, 중복 가설, 평가기 변조, 기준선 누락, 미래정보 누수, 재시작 멱등성, 비용 한도, 재현 메타데이터, 비인가 네트워크·시크릿, 보고서 숫자 근거.

12개 테스트는 계획된 요구사항이며 현재 이 문서 제작 과정에서 실행된 시스템 테스트가 아니다.
05 / FIRST BENCHMARK

R001 — Market Microstructure Discovery

NOT RUN
Falsifiable research question

가격 괴리는 발생 전에 식별할 수 있는가? 그리고 실제 비용과 독립적인 시간 분할 검증을 통과하는가?

승인된 과거 시장 데이터로 사례를 관찰하고, 가격 수렴·호가 불균형·측정 오류라는 경쟁 가설을 비교한다. 실제 거래는 수행하지 않는다.

Discovery

최대 30개 사례

가설을 만드는 초기 관측용. 선별된 30개를 수익성의 통계적 증명으로 사용하지 않는다.

Experiment

고정 평가기 + OOS

학습·검증·최종 테스트를 시간 순서로 나누고 지연·비용·체결 가능성을 평가한다.

Verdict

지지·기각·불확실

효과크기와 오차·반례를 보고하고, 경제적 수익을 보장하지 않는다.

Competing hypothesis candidates — not empirical findings
H1

일부 유동성 상태에서 괴리는 미래 수렴을 예측한다

기각 조건: 비용 반영 후 미지의 기간에서 효과가 사라짐.

H2

호가 불균형은 단순 기준선보다 추가 예측력을 제공한다

기각 조건: 동일 조건의 기준선을 이기지 못함.

H3

상당수 괴리는 데이터 시각·체결 가능성의 착시다

검증: 시각 정렬, 거래 깊이, 슬리피지, 비동기 호가로 재평가.

06 / ENGINEERING SEQUENCE

48시간 목표 → 30일 확장

둘 다 마감 압축을 위한 목표 일정이며 실현 가능성을 입증한 예측은 아니다. 최초 48시간은 한 번의 진짜 연구 루프를 완주하는 데 집중한다.

0–12 HOURS

실행 기반

환경 확인 · R001 계약 고정 · 실제 자료 수집 · 기준선 · 초기 가설.

12–24 HOURS

검증 엔진

평가기 고정 · 샌드박스 실행 · Run/Artifact/Decision 기록.

24–40 HOURS

하네스 강화

최초 E2E · 오류 처리 · 12개 방어 테스트 · 재시작 · 비용 제한.

40–48 HOURS

종결

독립 리뷰 · 재현 패키지 · 실패 포함 보고서 · 실행 여부 판정.

WEEK 01

Research Core

재현 가능한 단일 연구 루프와 운영 안정성.

WEEK 02

Domain Adapter

새 시간 구간 재현 + 두 번째 계산 연구 분야 연결.

WEEK 03

Evolution

가설 토너먼트·후보 DB·한도 있는 트리 탐색.

WEEK 04

Operations

재시작·중단·승인·보고·실험 비교 체계 정비.
